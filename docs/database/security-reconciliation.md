The consolidated schema is only for a fresh installation and ends with the same F0 reconciliation. Existing projects must apply the incremental migration, not re-run the whole consolidated schema. F0 itself is repeatable. Live pg_catalog visibility is not available through the service REST API; exhaustive definer catalogue assertions were run against the complete incremental schema in PGlite. Live authenticated tests confirm representative RLS/ACL behavior and should not be represented as an exhaustive penetration test.

Service-role RPC actor parameters are trusted only after backend token verification, capability checks and ownership validation. The database additionally checks Captain capability for the new recruitment/decision functions. Existing hub-review actor validation remains enforced by the trusted backend. Browser clients cannot invoke any mutation RPC directly.
