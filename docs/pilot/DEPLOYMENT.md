# F0 controlled deployment

Use one persistent Node server with HTTPS and WebSocket support. F0 chat subscriptions, rate limits and pending concierge actions are process-local; do not run multiple replicas. The database persists messages and retry keys. A restart expires pending in-memory action drafts.

## Backend

Install locked workspace dependencies, then `npm --prefix backend run build`. Deploy `backend/dist`, its copied `dist/rag/knowledge` directory, production dependencies and `backend/package.json`. Start `node dist/server.js` from the backend directory. Missing required RAG documents cause a clear startup failure.

Set `NODE_ENV=production`, `APP_DATA_MODE=production`, `PORT` (or local `BACKEND_PORT`), `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `AI_PROVIDER=gemini`, `AI_FALLBACK_PROVIDER=groq`, existing provider keys/models, and `ALLOWED_ORIGINS=https://your-web-domain`. Keys belong on the server. `SUPABASE_PUBLISHABLE_KEY` is used for public-key authentication setup where required. The startup log prints only the data mode, not keys.

Apply incremental migrations in order through `20261018000001_f0_stabilization.sql`. Do not reapply the consolidated schema to a live project. Run `backend/scripts/f0Preflight.ts` first; duplicate captain groups must be manually reviewed rather than deleted. F0 is transactional and aborts on duplicates. Existing INACTIVE roster entries become LEFT; all other history is preserved.

Production CORS matches exact configured web origins (comma-separated, no trailing slash). Native clients without an Origin header are supported, but every private REST/socket action still authenticates the token. Socket.IO checks origins for both polling and WebSocket handshakes. Add actual preview origins explicitly; do not use `*` in production.

Set `PAYMENT_MODE=disabled` for the first pilot. Existing reservation/payment code remains. Sandbox is the only other scope; fixed sandbox provider hosts prevent live-money activation. With disabled checkout users may contact a venue; that does not create a confirmed paid booking. A temporary Cloudflare URL is not permanent deployment.

## Web and Android

Set `EXPO_PUBLIC_APP_DATA_MODE=production`, `EXPO_PUBLIC_API_URL=https://api-domain`, Supabase public URL/key and optionally `EXPO_PUBLIC_SOCKET_URL` before exporting/building. Explicit URLs override LAN detection. `same-origin` is supported only when a reverse proxy intentionally serves REST `/api`, Socket.IO `/socket.io` and `/maps` on the frontend origin. No silent hosted same-origin assumption remains.

Configure Supabase's site URL and redirect allowlist for the actual web domain `/auth/callback` and the installed app's `maidaan://auth/callback`. Use the precise callback generated by the current auth helper. Keep Google's authorized redirect pointed at Supabase's auth callback. Re-test the complete OAuth round trip on web and the installed Android APK; a working email session does not prove Google OAuth.

The npm workspace lockfile is authoritative. Install from the repository root with `npm ci`; the stale Bun lockfile was removed after it caused a reproducible EAS frozen-lockfile failure. Do not regenerate a competing package-manager lockfile.

Android preview profile produces an internal APK. Run `npx eas-cli@latest login`, then `npx eas-cli@latest build --platform android --profile preview` from `mobile`. Authenticate the correct Expo account and link its project. Set the public backend/Supabase variables in that EAS environment before building; never add a service-role or AI key to EXPO_PUBLIC variables. Install the resulting APK on a physical device or emulator. Record device, Android version, build URL/ID, profile, date, and the F0 runtime checklist. An export is not installed-runtime evidence.

For local F0 acceptance, a `development` internal APK is being built under the linked `zaeeem17/maidaan` project because a permanent HTTPS backend is not configured yet. It connects to Metro on the same LAN. Start `npx expo start --dev-client`, open the installed Maidaan application and select the detected server or scan its QR code. A development APK requires Metro; it is not a standalone offline evaluation release. Use the preview profile with permanent backend configuration for distribution without Metro.

## Acceptance and operations

`backend/scripts/f0LiveAcceptance.ts` creates only disposable real Supabase accounts, upgrades a PLAYER through the real Captain setup API, tests matches/chat and hub/admin review, then deletes those accounts. `--keep` keeps a loopback-only server for browser checks; stop it with Ctrl+C to clean up. Session artifacts use ignored `.env.*` names and must never be published. Check `output/f0-live-evidence.json` for cleanup results. The script creates temporary listings labeled F0 DISPOSABLE; use a staging project where possible.

Before inviting real participants: backup/recovery policy, HTTPS hosting, final origin/redirect configuration, real owner inventory, Android installation and two-client browser acceptance must be recorded in PILOT-READINESS-REPORT.md. No production hosting account or deployment has been selected in this phase.
